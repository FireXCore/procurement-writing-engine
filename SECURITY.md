# Security boundary and release conditions

Status: development candidate, not approved for production. The library has no mutation/Apply API, no database access, no LLM, no analytics, no built-in public HTTP client and no default remote service. Optional providers are trusted code supplied by the deployment, not sandboxed plugins. Use only reviewed, pinned versions. No claim of a complete industrial parser or semantic safety.

* The application, not this library, authenticates users, determines tenant and field authorization, binds the current record/session/edit epoch, and supplies a complete authoritative region partition. `snapshotId` is an opaque correlation value, not an authorization credential. An absent, invalid, overlapping or incomplete region map blocks all provider calls.
* Protected ranges are never passed to providers. Other defensive checks exclude suspicious prose regions with numbers, technical punctuation, all-capital acronyms or mixed scripts. This deliberately reduces recall. Unknown plain-letter brand or supplier names still require protection by the host. Recheck the current authoritative context before rendering any result; clear the output on scope/value/permission change. No automatic suggestions should be applied.
* Offsets are half-open UTF-16 and grapheme-aligned; source slices and replacement restrictions are validated. A replacement can still alter a commercial promise or intent. A human must review it. The library is not a contract-law or engineering validator.
* Per-call deadlines and a total budget bound waiting on asynchronous providers. Cancellation is cooperative; a noncooperative provider retires the engine. Synchronous third-party code can still block its thread. Isolate browser execution in a worker owned by the application and terminate it on timeout, navigation, user/vendor/session changes. Dispose Harper instances at context boundaries. Do not share mutable linter dictionaries across tenants.
* The browser entry point does not import Node process/HTTP modules. Harper is initialized explicitly with a host-owned local binary (e.g., bundled `binaryInlined`); enforce CSP and inspect actual worker/WASM fetches before approval. Never initialize on login or load any external model from a CDN. No model provider is installed by this repository.
* Node transports are opt-in. LanguageTool only accepts explicit numeric IPv4 loopback HTTP URLs at `/v2/check`, rejects redirects, sends no cookies, and limits response size/time. Confirm service configuration disables external forwarding, logging of text, telemetry, and remote language-model calls. Vale and STE100 use absolute deployment-owned executable paths with fixed arguments, no shell, minimal environment, and bounded JSON output. STE100 writes a temporary plaintext file with restricted mode on POSIX and removes it in `finally`; Windows ACLs, crash cleanup, storage encryption and OS sandbox must be verified independently. Only synthetic inputs until this gate passes.
* Do not accept user-supplied executable paths, configs, plugins, rules, callbacks or provider endpoints. A trusted provider can access its runtime environment; OS/network sandbox and least privilege are mandatory for external processes. Process termination is not a complete descendant-process sandbox.
* Render findings as escaped plain text, never HTML. Diagnostics exclude exception messages; findings contain excerpts of authorized prose and must not be logged by applications. Do not store source text in browser storage or analytics.

Report vulnerabilities privately to the repository maintainer. Release and integration are blocked on the qualification checklist in `docs/RELEASE.md`.

## Security hardening candidate (not a release)
- Supported-script letters/marks are enforced for prose and replacements; protected data must still be declared by the authorized host. Common punctuation and emoji remain valid. Confusables within a supported script and plain-letter entity recognition are not solved by script validation.
- Core and adaptive review reject changes to a conservative list of critical commercial terms. This lexical check does not prove semantic equivalence. Findings are review-only; RMS must verify authoritative record, tenant, session, permission, exact source and region map before displaying or allowing any application.
- Public demo neural remote runtime is disabled at both UI and worker entry; the local fixed-corpus benchmark remains. Public demo preference learning is in-memory only; legacy origin-wide saved profiles are deleted without loading. Host-owned export/import remains available and requires explicit user/tenant scoping.
- Node adapters attempt hard termination and bounded cleanup on failure. OS process-tree sandbox, executable trust, Windows ACLs, crash cleanup and service logging remain deployment-owned gates. Do not import Node or model adapters into RMS browser integration.
- GitHub Actions references are pinned to full commit hashes; credentials are not persisted on checkout. This is hardening, not an upstream dependency audit. No automatic publication is authorized. Current release remains unchanged until a new independently qualified version is approved.
